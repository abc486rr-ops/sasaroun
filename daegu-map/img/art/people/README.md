## 다시 만들 때 — 밟았던 함정 세 가지

**1. 배경 판단 기준이 파일마다 다르다.**
`캐릭터24.png` 는 알파 없는 RGB 라 흰 배경을 밝기로 잡는다. 그 전 `캐릭터20.png` 는
배경이 알파 0 에 RGB 가 0(검정)이라, 밝기로 보면 배경이 가장 어두운 영역이 된다.
파일을 받으면 컬러타입부터 확인할 것.

**2. 인물 안쪽 흰 채움과 바깥 배경을 구분해야 한다.**
단순히 "흰색이면 투명"으로 처리하면 옷과 얼굴까지 뚫린다.
가장자리에서 시작하는 채우기(flood fill)로 **바깥에서 닿는 흰색만** 배경으로 본다.

**3. 그림이 칸 경계를 넘나든다.**
격자대로만 자르면 옆 칸 인물의 팔·가방·벤치 조각이 딸려 들어와 여백이 어긋난다.

남은 픽셀을 덩어리로 묶어 **가장 큰 덩어리 하나만 남긴다**(이번에 23개 걸러냄).
처음엔 "가장 큰 덩어리의 6% 미만은 버린다"로 했는데, p11·p23 에 넘어온 벤치가
6%·9% 라 살아남았다. 24칸 전부를 재보니 **2등 덩어리가 어디서도 9%를 넘지 않는다** —
인물은 예외 없이 하나로 이어진 덩어리다. 문턱값을 조정할 게 아니라 1등만 남기면 된다.

p12·p24 의 벤치는 인물과 붙어 있어 같은 덩어리라 그대로 남는다.

## 첫 화면 이미지에 loading="lazy" 를 걸지 말 것

추천인 아바타에 지연 로딩을 걸었다가 배포본에서 넉 장 모두 안 뜨는 일이 있었다.
로컬에서는 보이는데 GitHub Pages 에서만 빈 칸이었다. 뷰포트 교차 판정에 걸려
끝내 요청이 나가지 않은 것이다.

이 그림들은 첫 화면의 본문이다. 부수 이미지가 아니므로 즉시 로딩한다.
