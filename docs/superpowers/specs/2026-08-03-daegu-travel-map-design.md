# 사사로운이 추천하는 대구 여행 지도 — 설계

- 작성일: 2026-08-03 (월)
- 갱신: 2026-08-04 (화)
- 상태: 구현 중 — Phase 0~7 완료, Phase 8(실기기 검증) 남음
- 계획: `prompt_plan.md`

## 1. 목적

사사로운이 고른 대구의 장소 15~30곳을, 종이 제품 **여행갈피**와 짝이 되는 웹 지도로 만든다.

매장에서 여행갈피를 산 사람이 QR로 웹에 들어와 장소를 고르고, 방문한 곳을 체크한다. 온라인에서 링크로 들어온 사람에게는 사사로운의 큐레이션 자체가 콘텐츠가 된다.

## 2. 출발점

`smallbrand.archive.daegu.kr/map`(대백 전시, 유락 제작)의 **구조를 참고**한다. 코드는 가져오지 않고 처음부터 새로 쓴다. 저작권 문제가 없고 사사로운에 맞게 자유롭게 바꿀 수 있다.

원본에서 가져올 가치가 있다고 판단한 세 가지:

1. 물리적으로 고르는 손맛
2. 선택하면 지도로 내려앉는 다이빙 전환
3. history 기반 3뎁스 상태머신

가져오지 않는 것: 기어 UI(원본의 "엔진" 컨셉 산물), Three.js(133개 라벨용 과잉 사양), 절차적 오디오(공공장소 유입이 많아 위험).

## 3. 확정된 요구사항

| 항목 | 결정 |
|---|---|
| 대상·유입 | 매장 QR + 온라인 공유. 한국어 단일, 모바일 우선 |
| 데이터 | 추천인 + 장소. JSON 파일 하나. 이벤트로 매달 누적 |
| 첫 화면 | 추천인 목록 (팀 4명 + 이번 달 손님 1~2명) |
| 배포 | GitHub Pages. 서버·DB 없음, 운영비 0 |
| 사운드 | 없음 |
| UI 은유 | 여행갈피 카드 덱 (CSS 3D, WebGL 없음) |
| 위치 | 현재 `web` 저장소 안 `daegu-map/` |

## 4. 디자인 톤 — 여행갈피

`~/Desktop/디자인/책갈피/여행갈피.ai`에서 추출. 2페이지는 1페이지와 톤이 동일하다(사용자 확인).

### 색

| 토큰 | 값 | 용도 |
|---|---|---|
| `--sage` | `#DCDECF` | 헤더 블록, 카드 테두리 |
| `--paper` | `#F9F9F6` | 배경 |
| `--grid` | `#EFF0E8` | 모눈 선, 구분선 |
| `--card` | `#FEFEFE` | 카드 바탕 |
| `--ink` | `#343635` | 제목, 손그림, 강조 |
| `--sub` | `#5E605F` | 영문 라벨, 보조 텍스트 |

랜딩 페이지(`index.html`)의 금색 계열(`#C9A678`)은 쓰지 않는다. 별개 체계다.

### 타이포

여행갈피의 **영문 소문자 라벨(작게·연하게) + 한글 라벨(굵게·진하게)** 이중 구조를 UI 라벨 체계로 그대로 쓴다.

```
where to go          ← --sub, 작게
유락                  ← --ink, 굵게
```

이 구조는 원본 사이트의 영문 HUD 라벨(`COLLECTED` `SECTOR` `COORD`)과 정보 위계가 같다. 원본의 감각을 사사로운 방식으로 번역한 것이다.

### 배경

모눈종이를 CSS `repeating-linear-gradient`로 그린다. 이미지 파일 불필요.

### 일러스트

**확보 완료.** `.ai`에 박혀 있던 이미지 18컷을 투명 배경 PNG로 추출해 `daegu-map/img/art/`에 넣었다.

손글씨 `TRAVEL` `note` `go` `LOVE`, 배낭 멘 사람 2종, 기차, 비행기, 자동차 2종, 자전거, 사다리 2종, 머그컵, 아이스 아메리카노, 쇼핑백, 사람 셋.

원본이 벡터가 아니라 **래스터**다(폰트 정보 없음, 인덱스 CMYK 이미지). SVG로는 만들 수 없다.

**해상도 제약:** 가장 큰 컷이 592×144다. 레티나 2배 밀도를 지키려면 표시 폭을 원본의 절반 이하로 잡는다(예: 기차 296px, 걷는 사람 69px). 더 크게 써야 하면 원본 작업 파일에서 다시 뽑아야 한다.

용도: 로딩 화면, 빈 상태, 사진 없는 장소의 플레이스홀더, 섹션 구분.

## 5. 아키텍처

빌드 도구 없음. 네이티브 ES 모듈. GitHub Pages 그대로.

```
daegu-map/
├─ index.html          마크업 + OG 태그 + 크리티컬 CSS
├─ data/places.json    추천인 + 장소
├─ og.png              공유 카드 (손그림으로 합성)
├─ vendor/leaflet.*    자체 호스팅
├─ img/art/            손그림 PNG 18컷
├─ css/                tokens · shell · curators · deck · map
├─ js/                 main · data · state · curators · deck · map · card · visited
└─ test/               data · state · state-timers · visited
```

원본은 1,122줄 단일 파일이었다. 각 모듈 200줄 이하로 나눈다.

### 의존성

**Leaflet 하나뿐.** `vendor/`에 자체 호스팅한다.

GSAP은 쓰지 않는다. 이 저장소 `index.html:415-425`에 이미 포인터·터치·휠을 다루는 스와이프 카루셀이 있고, 카드 20장에는 그 패턴을 확장한 CSS transition으로 충분하다.

Three.js·troika·webgl-sdf-generator·bidi-js를 모두 걷어낸 결과, WebGL 컨텍스트 손실 방어 코드도 함께 불필요해진다.

## 6. 상태머신

| 뎁스 | 화면 | URL |
|---|---|---|
| CURATORS(0) | 추천인 목록 | `/daegu-map/` |
| DECK(1) | 그 사람의 장소 카드 덱 | `#/박사장` |
| MAP(2) | 카드가 뒤집히며 지도 노출 | `#/박사장/유락` |

`TRANSIT`는 전환 중 입력을 막는 잠금 상태다.

### FOCUSED 뎁스를 없앤 이유

애초 설계는 `DECK → FOCUSED → MAP`이었다. 추천인 목록이 앞에 붙으면 4단이 되는데, 모바일에서 뒤로가기를 네 번 눌러야 처음으로 돌아가는 건 과하다.

`FOCUSED`는 원본 사이트의 유산이다. 기어에 133개 라벨이 깨알같이 박혀 있으니 하나를 크게 키워 보는 단계가 필요했다. 우리 덱은 **한 번에 카드 한 장을 화면 폭으로** 보여주므로 이미 확대된 상태다. 한 줄 소개도 추천 이유도 덱 카드에 다 들어간다.

따라서 덱에서 카드를 탭하면 바로 지도로 내려간다. 뎁스는 3단을 유지한다.

### 뒤로가기

모든 '뒤로'(버튼·ESC·카드 닫기)는 `history.back()` 하나로 통일한다. `popstate`가 목표 뎁스를 갱신하고 `reconcile()`이 한 단계씩 역재생한다. 앞으로가기는 지원하지 않으며 `replaceState`로 현재 상태에 재정렬한다.

### 원본에서 고치는 점 — 전환 타임아웃 폴백

원본은 전환 완료를 애니메이션 완료 콜백에만 의존한다. 콜백이 유실되면 `TRANSIT`에서 영원히 벗어나지 못하고, 복구 수단이 없다.

우리는 전환 시작 시 **1.5초 타임아웃**을 함께 건다. 콜백이 먼저 오면 타임아웃을 해제하고, 타임아웃이 먼저 오면 목표 상태를 강제로 확정한다. 코드 세 줄이고 사용자가 화면 앞에서 멈추는 최악의 경우를 막는다.

## 7. 덱 인터랙션

- 스와이프 1회 = 카드 1장 이동. 관성으로 여러 장이 넘어가지 않는다
- 이동 거리가 카드 폭의 25% 미만이면 원위치로 되돌린다
- 양 끝에서는 더 넘어가지 않고 살짝 밀렸다 돌아온다 (순환하지 않음 — 몇 곳을 봤는지 감각이 남아야 한다)
- 하단 점 인디케이터로 현재 위치 표시
- 카드를 탭하면 바로 MAP
- 키보드: `←` `→` 이동, `Enter` 진입, `ESC` 뒤로

## 7-1. 추천인 목록 (CURATORS)

첫 화면이다. 지도가 "장소 모음"이 아니라 "사람의 취향 모음"이 되는 지점이라, 이 화면이 서비스의 성격을 결정한다.

- 추천인 카드를 세로로 나열. 이름 · 한 줄 특징 · 추천 장소 수 · 방문 진행률
- 여행갈피 손그림을 추천인마다 하나씩 배정해 얼굴 대신 쓴다 (사진 불필요, 익명성 유지)
- 상시 노출: **팀 추천인**(`kind: "team"`)
- 그 아래: **이번 달의 손님**(`kind: "special"` 중 `month`가 이번 달인 것)
- 맨 아래 접힌 영역: 지난 달 손님들

### 스페셜 추천인 = 이벤트

손님이 매장에서 산 여행갈피에 다녀온 곳을 적어 남기면, 사사로운이 그중 매달 1~2명을 골라 추천인으로 올린다. **종이 여행갈피가 곧 응모 용지다.** 웹 제출 폼도 백엔드도 필요 없다.

"교체"는 지우는 게 아니라 이번 달 자리에서 내려오는 것이다. 지난 손님은 아래 접힌 영역에 남는다. 매달 쌓이는 게 이 지도의 자산이다.

## 8. 다이빙 전환

원본은 WebGL 캔버스를 `opacity: 0`으로 내려 아래 지도를 드러낸다.

우리는 **카드만 `rotateY`로 뒤집혀 사라지고, 그 아래에서 전체 화면 지도가 올라온다.** 지도는 3D 변환 컨텍스트 바깥의 독립 레이어다. 발상은 같고 WebGL은 없다.

지도가 드러난 뒤 Leaflet의 `invalidateSize()`를 호출해 타일을 다시 계산한다. 숨겨진 요소에서 초기화된 지도는 크기를 잘못 잡는다.

애초에는 카드 뒷면을 지도 컨테이너로 삼으려 했다. 아래 스파이크 결과가 그 판단을 바꿨다.

### 스파이크 결과 (2026-08-04)

`spike-3d-map.html` 로 `rotateY(180deg)` + `preserve-3d` + `backface-visibility: hidden` 안의 Leaflet과 바깥의 Leaflet을 나란히 두고 비교했다.

| 항목 | 3D 안 | 3D 밖 |
|---|---|---|
| 컨테이너 크기 인식 | 580×220 | 580×220 |
| 타일 로드 | 6 | 6 |
| 화면 좌표 → 위경도 오차 | 1.72 m | 1.72 m |

**Chromium에서는 차이가 없다.** 1.72m는 두 경우 모두 동일한 픽셀 반올림 오차다.

**iOS 사파리에서도 동일하다** — 사용자가 실제 아이폰으로 이 페이지를 열어 확인했다(2026-08-04). 애초 "높음"으로 잡았던 위험은 근거가 약했다.

**그래도 지도는 3D 바깥에 둔다. 다만 이유가 바뀌었다 — 3D 위험이 아니라 화면 크기다.**

카드 뒷면을 지도로 쓰면 지도가 카드 크기에 갇힌다. 전체 화면으로 보려면 카드를 뷰포트 크기로 키운 뒤 뒤집어야 하고, 그러면 화면만 한 3D 레이어 안에서 타일을 합성하게 된다. 600ms짜리 연출을 위해 치를 비용이 아니다.

여행 지도에서 지도는 넓어야 한다. 카드는 뒤집혀 사라지고, 그 아래에서 전체 화면 지도가 드러난다. 보이는 결과는 "카드가 뒤집혀 지도가 되었다"로 같다.

`spike-3d-map.html` 은 목적을 다해 제거했다(커밋 `44c9853` 이후).

## 9. 데이터

추천인과 장소를 **분리한다.** 두 사람이 같은 곳을 추천해도 장소는 하나만 둔다.

```json
{
  "curators": [
    {
      "id": "parksajang",
      "name": "박사장",
      "kind": "team",
      "tagline": "조용하지만 감성적인 곳",
      "traits": ["30대 후반", "INTJ"],
      "intro": "추천인 소개 1~2문장",
      "art": "art-057-138x189.png",
      "places": ["yurak", "neuel", "ecc"]
    },
    {
      "id": "guest-2026-08",
      "name": "손님 닉네임",
      "kind": "special",
      "month": "2026-08",
      "tagline": "한 줄 특징",
      "traits": [],
      "intro": "여행갈피에 남겨주신 기록에서",
      "art": "art-062-118x184.png",
      "places": ["kawa-archive"]
    }
  ],
  "places": [
    {
      "id": "yurak",
      "name": "유락",
      "sector": "카페",
      "lat": 35.8606,
      "lng": 128.5984,
      "one_liner": "카페처럼 보이는 프로젝트 사무실",
      "note": "사사로운이 추천하는 이유 2~3문장",
      "photo": "img/places/yurak.jpg",
      "hours": "12:00–21:00 · 월 휴무",
      "walk": "반월당역 7분",
      "link": "https://instagram.com/...",
      "added": "2026-08-04"
    }
  ]
}
```

### 한 줄 평은 추천인의 것이다

`note`(한 줄 평)는 장소가 아니라 **추천인의 `places` 참조 안에** 붙는다.

같은 곳도 사람마다 다르게 말한다. 사사로운을 두고 박사장은 "의미를 전하는 소품샵", 정토브는 "예쁜 책갈피를 샀지", 김먼지는 "한시간 순삭...텅장..." 이라고 적었다. **그 차이가 이 지도의 내용**이므로 장소당 하나로 뭉개면 안 된다.

참조는 문자열로도 객체로도 적을 수 있다.

```json
"places": ["yurak", { "id": "sasaroun", "note": "예쁜 책갈피를 샀지" }]
```

`traits`는 자유 목록이다. 나이대·MBTI·취향 무엇이든 들어갈 수 있고 비어 있어도 된다. 개인 정보를 강제로 채우게 만들지 않는다.

`art`는 `img/art/`의 손그림 파일명이다. 추천인마다 하나씩 배정해 얼굴 사진 대신 쓴다.

### 좌표는 선택이다 (2026-08-04 변경)

애초에는 좌표를 필수로 잡았다. 실제 데이터를 받아보니 25곳 중 13곳의 좌표를 구할 수 없었다 — 대백 아카이브에는 2곳뿐이고, OpenStreetMap 에는 작은 가게가 거의 올라와 있지 않다.

좌표가 없다고 그 장소를 버리면 **추천 이유까지 함께 사라진다.** 그런데 이 지도의 내용은 추천 이유이고 핀은 그다음이다. 그래서 좌표를 선택으로 바꿨다.

- `lat`·`lng` 는 **둘 다 있거나 둘 다 없어야** 한다. 하나만 있으면 제외한다
- 검증이 `located` 플래그를 붙인다. 지도는 이 값이 참인 곳만 핀을 찍는다
- 핀 번호는 덱 순서를 그대로 쓴다 — 카드의 `N°003` 과 지도의 `3` 이 같아야 한다
- 좌표 없는 장소를 열면 지도는 그 추천인의 나머지 장소 전체를 보여주고, 카드에 "위치 확인 중"을 적는다. 네이버지도 링크는 이름으로 검색하므로 그대로 동작한다

`photo`·`link`는 선택. 없으면 손그림 플레이스홀더와 링크 없는 카드로 처리한다.

### 외부 지도 링크

장소 카드에 **네이버지도** 링크 하나를 건다. 새 탭으로, 길찾기가 아니라 장소 표시로 연다.

카카오맵도 함께 걸어봤으나 뺐다. 카카오맵 앱이 링크 주소를 네이티브 지도가 아니라 앱 내장 브라우저로 열어, 두 링크의 동작이 달랐다. 링크가 서로 다르게 굴면 그 자체가 걸림돌이 된다.

네이버는 좌표가 아니라 **이름으로 검색**한다. 우리가 부르는 이름과 지도 등록 상호가 다르면 엉뚱한 곳이 나온다. 그런 장소는 선택 필드 `map_query`에 검색어를 따로 적는다.

```json
{ "name": "E.C.C", "map_query": "이씨씨커피" }
```

없으면 `name`으로 검색한다. 장소를 추가할 때는 네이버지도에서 한 번 검색해보고 상호가 다르면 채운다.

현재 값(2026-08-04 확인):

| 장소 | `map_query` |
|---|---|
| 사사로운 | 사사로운 소품샵 |
| 유락 | **야행성동물** |
| 카와아카이브 | 카와 아카이브 소품샵 |
| E.C.C | 이씨씨커피 |
| 디카프리M1955 | 디카프리 M1955 |
| 낭만젊음사랑 · 느을 | (없음 — 이름이 그대로 등록돼 있다) |

**유락은 네이버지도에 등록돼 있지 않다.** 같은 주소에서 운영하는 '야행성동물'로 검색한다. 오타로 보여 고치기 쉬우므로 `places.json` 의 `meta.notes` 에도 적어뒀다.

### 검증 (경계에서)

로드 직후 각 항목을 검사한다.

- `id`·`name`·`lat`·`lng`·`one_liner` 필수
- 좌표가 대구 범위(위도 35.6~36.0, 경도 128.3~128.8) 밖이면 제외
- `id` 중복이면 뒤엣것 제외

실패 항목은 콘솔에 경고를 남기고 목록에서 빼되, **나머지는 정상 표시한다.** 한 항목의 오타로 전체가 죽지 않게 한다.

추천인도 같은 방식으로 검사한다.

- `id`·`name`·`kind`·`places` 필수
- `kind`가 `special`이면 `month` 필수 (`YYYY-MM`)
- `places`의 원소가 실제 장소 `id`와 맞지 않으면 그 항목만 제외
- `places`가 비면 추천인 자체를 목록에서 제외

한 장소가 여러 추천인에 속하는 건 정상이다. 덱에서는 `added` 최신순으로 정렬하고, 최근 30일 내 항목엔 `new` 배지를 단다.

## 10. 방문 체크

여행갈피 종이 제품의 방문지 체크박스를 웹으로 옮긴다.

- 카드마다 "다녀왔어요" 체크박스
- `localStorage`에 `id` 배열로 저장 (키: `sasaroun.daegu.visited`)
- 덱 상단에 `3 / 24` 형태로 진행 표시
- 저장 실패(사파리 프라이빗 모드 등)는 조용히 무시한다. 체크가 안 될 뿐 지도는 정상 동작해야 한다

서버가 없으므로 기기 간 동기화는 하지 않는다. 종이 제품이 원본 기록이고 웹은 보조다.

## 11. 에러 처리

## 12. 공유

- OG 태그: `og:title` `og:description` `og:image` + `twitter:card`
- `og:image`는 **완성됨** — `og.png` 1200×630. 추출한 손글씨 `TRAVEL` `note` 와 배낭 멘 사람·기차·사다리를 모눈 배경 위에 합성했다. 폰트 렌더링 없이 제품의 손글씨를 그대로 쓴다

### 제약 — 장소별 OG 미리보기는 불가

GitHub Pages는 정적 호스팅이라 `/daegu-map/유락` 같은 경로 라우팅을 할 수 없다. 원본은 서버가 있어서 가능했다.

따라서 해시 라우팅(`#/박사장`, `#/박사장/유락`)을 쓰고, **공유 카드는 어느 화면에서나 동일하다.** 추천인별·장소별로 다른 미리보기가 필요해지면 Vercel 등으로 옮겨야 하며, 그때는 별도 결정 사항이다.

해시에는 `id`가 아니라 사람이 읽을 수 있는 이름을 쓴다. 링크를 보고 누구의 추천인지 알 수 있어야 공유에 의미가 생긴다.

## 16. 다음 작업 — 전체 목록 화면 (제안, 미구현)

사용자 요청(2026-08-04): 25곳을 한 번에 보는 지도와 목록. 각 장소를 몇 명이 추천했는지도.

### 뎁스를 늘리지 않는다

`ALL` 을 `DECK` 과 **같은 층(1)** 에 둔다. 덱이 "한 사람의 카드 묶음"이라면 ALL 은
"모두의 목록"이다. 성격이 다를 뿐 위치는 같다.

```
CURATORS(0) ─┬─ DECK(1)  #/박사장       → MAP(2)  #/박사장/유락
             └─ ALL(1)   #/전체         → MAP(2)  #/전체/유락
```

3뎁스가 유지되고 뒤로가기 규칙도 그대로다. `state.js` 는 손댈 필요가 없다 —
`machine.request(DECK, ctx)` 에 `ctx.all = true` 를 실어 보내면 된다.

### 화면

- 추천인 목록 맨 아래에 **"25곳 한눈에 보기 →"** 를 둔다
- 목록은 카드 덱이 아니라 **세로 리스트**다. 25개를 넘기게 하면 손이 아프다
- 행마다: 번호 · 이름 · 업종 · **추천인 아바타 겹쳐 표시** · 방문 체크
- 여러 명이 추천한 곳은 아바타가 겹쳐 쌓이므로 셀 필요 없이 눈에 띈다
- 정렬: 추천인 수 많은 순 → 그다음 `added` 최신순

### 추천 수 집계

`data.js` 에서 파생값으로 만든다. 데이터에 중복해 적지 않는다.

```js
// placeId → [curator, ...]
const byPlace = new Map()
curators.forEach(c => c.places.forEach(({id}) => {
  byPlace.set(id, [...(byPlace.get(id) ?? []), c])
}))
```

현재 겹치는 곳: 사사로운 3명, 브라운 슈가 2명, 서문시장 2명, 소베 2명.

### 지도

`map.setPlaces(전체 25곳)` 로 그대로 쓴다. 핀 번호는 목록 순서를 따른다.
장소 카드에 **"3명이 추천"** 과 추천인 이름을 넣고, 각 이름을 누르면 그 사람의 덱으로 간다.

### 남은 확인

- 25개 핀이 한 화면에 들어가면 이름표가 겹친다. 줌 레벨에 따라 이름표를 숨기거나,
  겹칠 때만 번호만 보이게 하는 처리가 필요하다
- 레헴(달성군)·폭스브롯(달서구)이 멀어 `fitAll` 하면 도심이 뭉개진다.
  전체 보기의 초기 뷰를 도심 기준으로 잡고 "전체 보기" 버튼을 따로 둘지 검토
